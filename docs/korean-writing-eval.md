# ChatGPT.md 검증 세트 (Korean Writing Eval)

> **목적**: ChatGPT.md 지침이 실제로 한국어를 모어 화자답게 쓰게 하는지 확인한다. 지침을 넣기 전(기본 ChatGPT)과 넣은 후를 같은 프롬프트로 비교해, 후자가 (1) 더 자연스럽고 (2) 사실과 의미는 그대로이며 (3) 상황에 맞는지 본다. 이 검증은 ChatGPT에서 사람이 돌린다(Claude가 대신 못 함).

## 사용법

1. ChatGPT 맞춤 지침(또는 프로젝트 지침)에 ChatGPT.md 내용을 넣는다.
2. 아래 프롬프트를 (A) 지침 없이, (B) 지침 넣고 각각 돌린다.
3. 두 출력을 채점 기준으로 비교한다.
4. 판정:
   - 지침이 먹히면: B가 A보다 뚜렷이 자연스럽고, 충실성은 유지된다.
   - 과교정: B가 딱딱하거나 어색하면 지침이 자연스러움을 해친 것이다.
   - 안 먹힘: B가 여전히 번역투면 지침이 작동하지 않은 것이다.
   - 충실성 실패: B가 사실이나 의미, 초점을 바꿨으면 문제다.

## 채점 기준 (각 출력에 O/X)

1. **자연스러움**: 모어 화자가 그 상황에서 실제로 쓸 문장인가(영어식 어순, 번역 계열 어휘 없음).
2. **충실성**: 윤문이면 원문의 사실, 수치, 의미, 초점을 보존했는가. 생성이면 요청 내용에 충실한가.
3. **상황 적합성**: register가 상황에 맞는가(친구엔 구어, 보고서엔 반듯).
4. **AI 티 부재**: 상투구('시사하는 바가 크다' 등), 불필요한 이모지, 장식 불릿 남발, 명사화 남발, 피동 남발이 없는가.
5. **번역투 표지 부재**: '~에 대해', '~에 의해', '~을 통해', '~들', '그것', '~에 있어서', 겹조사 남용이 없는가.

## 프롬프트 세트

### 생성

- **G1 (보고서, 번역투 유발)**: "생성형 AI가 소프트웨어 개발 생산성에 미치는 영향을 세 문단으로 설명해줘."
  - 볼 것: 명사화, 수동태, '~에 의해', '~을 통해' 남발 여부와 상투구, 불릿과 이모지 남발. 좋은 출력은 동사 중심에 능동이고 흐름이 자연스럽다.
지침 미사용
```
생성형 AI는 코드 작성, 자동 완성, 오류 수정, 테스트 코드 생성과 같은 반복적인 업무를 지원해 소프트웨어 개발 속도를 높인다. 개발자는 자연어로 요구사항을 설명하고 코드 초안을 얻을 수 있으며, 익숙하지 않은 언어나 프레임워크를 사용할 때도 예제와 설명을 빠르게 확인할 수 있다. 이에 따라 구현에 필요한 시간이 줄어들고, 개발자는 설계와 문제 해결처럼 더 높은 수준의 업무에 집중할 수 있다.

또한 생성형 AI는 문서 작성, 코드 리뷰, 리팩터링, 디버깅 등 개발 전반의 효율성을 향상한다. 예를 들어 복잡한 코드의 동작을 요약하거나 잠재적인 오류를 찾아 개선안을 제시할 수 있으며, API 문서와 주석도 자동으로 작성할 수 있다. 이러한 기능은 팀원 간 지식 격차를 줄이고 신규 개발자의 학습 속도를 높여 조직 전체의 생산성 향상에 기여한다.

그러나 생성형 AI가 만든 코드가 항상 정확하거나 안전한 것은 아니다. 잘못된 로직, 보안 취약점, 비효율적인 구현 또는 라이선스 관련 문제가 포함될 수 있으므로 개발자의 검토와 테스트가 반드시 필요하다. 따라서 생성형 AI는 개발자를 대체하는 도구라기보다 개발자의 판단을 보조하는 도구로 활용해야 하며, 적절한 검증 절차와 보안 정책을 함께 적용할 때 가장 큰 생산성 효과를 얻을 수 있다.
```
지침 사용
```
생성형 AI는 코드 작성, 테스트 생성, 문서화, 오류 원인 탐색 같은 반복 작업을 빠르게 처리해 개발 시간을 줄인다. 특히 익숙한 패턴의 기능을 구현하거나 새로운 라이브러리의 사용법을 파악할 때 효과가 크다. 개발자는 초안을 직접 만드는 대신 AI가 제안한 결과를 검토하고 수정하는 방식으로 작업 속도를 높일 수 있다.

다만 생산성 향상이 곧바로 소프트웨어 품질 향상으로 이어지지는 않는다. AI가 만든 코드는 겉보기에는 그럴듯해도 보안 취약점, 잘못된 예외 처리, 불필요한 복잡성을 포함할 수 있다. 검증 없이 사용하면 이후 디버깅과 유지보수 비용이 커지므로 코드 리뷰, 테스트, 보안 점검은 오히려 더 엄격해져야 한다.

실제 효과는 개발자의 숙련도와 조직의 개발 방식에 따라 달라진다. 숙련된 개발자는 AI의 오류를 빠르게 찾아내며 생산성을 높이지만, 경험이 부족한 개발자는 잘못된 결과를 그대로 받아들일 가능성이 있다. 따라서 생성형 AI의 성과는 작성한 코드의 양보다 개발 주기 단축, 결함률, 변경 실패율, 유지보수 시간처럼 품질과 속도를 함께 보여주는 지표로 평가하는 편이 적절하다.
```

## 판정 종합

- 다섯 기준을 대체로 통과하고 B가 A보다 자연스러우면 지침이 작동한다.
- 특정 기준이 반복해서 무너지면 그 부분을 지침에서 손본다. 예를 들어 E3에서 구어가 문어체로 바뀌면 과교정이니 톤 규칙을, G1이 여전히 번역투면 번역투 예시나 동사 중심 규칙을 다시 본다.
- 결과를 알려주면 어느 규칙을 고칠지 함께 정한다.
